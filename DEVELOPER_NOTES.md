# Developer Notes & Guidelines

This file serves as a persistent set of instructions and guidelines that I will ALWAYS check before making decisions or documenting code.

## Documentation Guidelines
1. **Always Read the Code First**: Never assume the implementation details of a function based purely on its signature. Always view the source `.c` file and read the actual code block before writing the description.
2. **Highlight Key Optimizations**: Make sure to explicitly point out advanced architectural choices, such as Computed Gotos, DFS iterative stack traversals, and Pratt parser precedence tables.
